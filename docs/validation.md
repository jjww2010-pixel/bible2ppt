# 자동 검증 범위

## 본문·제작 작업 검사

원문을 포함하지 않는 형식 전용 자료로 66권, 1,189장, 31,088개 본문 항목을 생성합니다.
11개 통합 절과 45개 이어진 줄, 생략된 절 번호도 재현합니다.
프로그램의 본문 가져오기, SQLite 초기화, 구절 해석·선택 경로에서 31,101개의 개별 절 요청을 검사합니다.
통합 절의 뒤쪽 절을 요청해도 통합 본문이 한 번만 선택되는지 검사합니다.

별도 제작 작업 테스트는 실제 `Builder`를 실행하고, PowerPoint 입출력만 기록용 구현으로 바꿉니다.
전체 성경, 여러 구절, 장을 넘는 구절, 장별 파일 분할, 잘못된 입력, 누락된 장·절·책,
제작 취소, 제작 중 입출력 오류, 저장 실패, 오류 후 다음 작업을 확인합니다.
이 테스트는 실제 PowerPoint의 슬라이드 렌더링을 검증한 것으로 간주하지 않습니다.

## Windows 실행 파일 검사

Actions → **Windows EXE**가 Windows 서버에서 x64와 x86 EXE를 만들고 직접 실행합니다.
별도의 .NET 설치를 요구하지 않는 배포 파일을 한글·공백 경로에 복사해서 테스트합니다.
정상·오류·없는 JSON/TXT, CP949, 전체 형식 자료를 검사합니다.

`--check-ui` 검사는 실제 `MainForm`을 열고 다음을 조작·검사합니다.

- 로컬 성경 자동 선택과 66권 목록 로딩
- 제작·기록·설정 화면 전환 (원작의 미완성 템플릿 목록 메뉴는 숨긴 상태 유지)
- 기본 PPT 템플릿 추출과 슬라이드 XML 존재
- 요한일서 검색과 `요일 4:8` 입력
- 성경 선택 제거·추가와 설정 값 변경
- 새 설정, 잘린 설정 파일, 잘못된 줄 수 설정

UI 검사에서 PowerPoint 렌더러만 비활성화합니다. Windows 서버에는 Microsoft Office가 설치되어 있지 않습니다.
Office COM 초기화, 실제 슬라이드 생성·모양, 사용자 지정 템플릿과 Office 버전별 차이는 이 서버에서 확인할 수 없습니다.
이를 확인하는 `Check-PowerPoint.cmd`는 PowerPoint가 있는 Windows PC용으로 배포본에 포함합니다.

## 결과 확인

각 Windows 실행은 원본 커밋, 운영체제, 테스트 결과, EXE 검사 결과, TRX와 개별 검사 보고서를
`verification-win-x64-...` 또는 `verification-win-x86-...` 브랜치에 저장합니다.
Actions 실행의 **verification-win-x64/x86** 산출물에서도 확인할 수 있습니다.
통과한 실행만 같은 결과 브랜치에 검사한 EXE의 ZIP을 올립니다.
실패·생략은 통과로 기록하지 않으며, 보고서의 커밋이 다운로드한 배포본과 일치하는지 확인합니다.

실제 가져온 본문은 `Check-Bible.cmd`로 전체 구절 요청을 한 번에 검사할 수 있습니다.
이 검사는 파일의 조회·선택 일관성을 검사하며 번역 문장의 정확성이나 본문 완전성을 보증하지 않습니다.
